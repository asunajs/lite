# lite 踩坑排查

按**技术主题**组织，每节是「现象 → 根因 → 现在怎么防」。想写代码看
[`guide.md`](guide.md)，想改框架看 [`design.md`](design.md)。

这里记的是**已经修掉的问题**：写下来是为了下次能一眼认出同族的症状。
现在的行为以源码与 [`design.md`](design.md) 为准。

## 「锚点：动态子节点为什么会错位」

**现象**：动态子节点（组件 / 元素 / 条件分支）插错位置或顺序颠倒；相邻两个动态子节点的先后取决于谁的 effect 先跑；更新抛 `insertBefore` 的 `NotFoundError`，或文本节点被当成父节点报 `HierarchyRequestError`。

**根因**：动态子节点必须由"编译期算出的 `childNodes[i]` + 占位锚点"钉住位置；没有锚点时只能追加到末尾，顺序就变成 effect 的执行顺序。两件事还会让下标算错：非空元素写成自闭合（`<label />` 生成的 HTML 没有自闭合，兄弟被解析成它的子节点）、相邻文本在 HTML 解析后合成一个节点。

**现在怎么防**：
* 每个动态子节点自带 `<!---->` 占位注释当锚点（`setNodes` / `createFor` 都接 anchor），重跑多少次都插在同一处；
* 非空元素一律补出闭合标签；空元素带子节点直接编译报错；文本按合并后的下标算；
* `insert()` 遇到"锚点已不在父节点里"退化为追加并 `console.warn`，不让一次 `insertBefore` 抛穿整次更新；
* **不要手动增删 / 搬动框架生成的节点** —— 动态位置就是靠那些占位注释定位的。

## 「effect 的归属：什么时候必须销毁」

**现象**：切页 / 条件分支 / 列表删行之后，控制台抛 `Failed to execute 'insertBefore' on 'Node'`；或页面已经不在了，它注册的回调还在跑。反过来也有：反复进出某一页，节点数只增不减。

**根因**：`remove()` 一度只跑卸载钩子、不销毁 effect ⇒ 被移除子树里的 effect 还订阅着全局
信号，信号一变就拿着已经不在文档里的 parent / anchor 去插节点。同一族的还有槽：`lazySlot`
只把占位文本节点交给调用方，碎片内容由槽自己的 effect 插在占位后面 —— 父槽重跑时只摘占位、
内容留下，于是每刷一次多一整套。

**现在怎么防**：
* 编译器生成的绑定按**节点**记账（`dom.ts` 的 `owners`）：节点被 `remove()` 摘走时 `disposeTree()` 连带销毁；
* 组件体内手写的 `effect()` / `watch()` 按**组件实例**记账，组件卸载即停；只有组件外面（模块级）建的才要自己 `dispose()`；
* effect 重跑前先看"上次插进去的节点还在不在文档里"，全都不在就自己 `dispose()`（管的是"父还活着、子树已被换掉"）；
* 槽按占位节点记账 `{fn, nodes, eff}`，`remove()` 把它插进去的所有节点一起收掉（递归：碎片里可能还嵌槽）；
* 列表**行内**的 effect 要挂到行节点下，否则 `remove(row.nodes)` 收不掉。

## 「挂载期间写信号 ⇒ 外壳被重入渲染」

> **2026-10-08 复测：现在复现不出来了。** 见本节末尾的实测记录 —— 病因已在运行期堵住。
> 保留本节是因为**症状描述与排查手法仍然有效**，但"所以挂载期不能写信号"这条**不再是硬约束**。

**现象**：切页时旧页面不被替换、新页面被**追加**，容器里的块数一路累加，页面上同时挂着好几个
页面，某一页的 `loading` 永远留在 DOM 里。

**根因**（当时）：更新是**同步**的，而"页面挂载的那一刻"正是外壳在渲染这一页的过程中 ⇒ 此时写
信号会立刻重入外壳的渲染，`setNodes` 的替换路径被打断：新节点被追加、旧节点留在原地。

**为什么现在不容易碰到了**：`setNodes` 与 `lazySlot` 各自加了守卫 ——
* `setNodes`：上次插的节点**全都**不在文档里 ⇒ 这条 effect 自毁（管"父还活着、子树已被换掉"）；
* `lazySlot`：内容与占位绑定，被整块换掉后旧槽不再往文档里补节点。

两者合起来把"退化成追加"那条路堵死了（提交："陈旧 effect 自毁 —— 真机'越刷新内容越多'的根因
（撤回'退化为追加'的取舍）"）。

**仍要注意的**（与"写信号"无关，是记账问题）：组件体内手写的 `effect()` / `watch()` 按组件实例
记账，卸载即停；**模块级**建的才要自己 `dispose()`。子组件的 `onMounted` 先于父页面跑，所以
"给外壳登记回调"仍应推到 `queueMicrotask`（否则会被父页面盖掉）—— 但这是**登记顺序**问题，
不是本节的渲染问题。

**复测记录（2026-10-08，`demo/main.tsx` 的 EXP 段）**

4 种组合实测，全部是"每页各建一次、节点不累积"：

| 组合 | 结果 |
|---|---|
| 外壳触发 + 新页不写信号 | 子节点 5→5，A 重建 1、B 重建 1 |
| 子树内触发 + 新页不写信号 | 子节点 4→4，A 重建 1、B 重建 1 |
| 子树内触发 + **挂载期写信号**（外壳读它） | 子节点 4→4，A 重建 1、B 重建 1 |
| 同上但推到微任务 | 完全一样 |

## 「同步跨视图跳转 ⇒ 新页被无限重建」

> **2026-10-08 复测：现在复现不出来了。** 结论直接改变了 `router.ts` 的实现（同步，不推微任务）。
> 保留本节是因为**症状与三步排查法**在复发时仍然是最快的入口。

**现象**：新页停在 loading，组件体被反复重建上千次（每次挂载都重发一轮请求）。

**根因**（当时）：在事件处理器（或 effect）的求值还没退栈时**同步**换页 —— 当前页在"这个点击
处理器还没退栈"时就被整棵拆掉，新页的挂载又落回同一个未退栈的调用链里。与上一节同族。

**复测记录（2026-10-08）**：在上一节 4 组之外又加了两轮，共 **8 组**，**没有任何一组复现**：

| 组合 | 结果 |
|---|---|
| 挂载期"重定向"（写的是**驱动换页的同一个信号**）+ 同步 | 子节点 2→2，A/B/C 各建 1 次，只有 C 在文档里 |
| 同上 + 推到微任务 | 完全一样 |
| **`watch` 命令式切页**（`watch(page, () => { unmount(); mount(next) })`，在产项目的形态）+ 同步 | 槽内节点 1→1，A 重建 1、B 重建 1、A 残留 0 |
| 同上 + 推到微任务 | 完全一样 |

⇒ **"同步换页"本身不构成触发条件**；当年的病因是"退化成追加"那一类，已由上一节的守卫堵住。
所以 `createRouter` 是**同步**的（与 `signal.ts`"同步 + 批量、不引入 nextTick"的原则一致），
`navigate()` 返回时状态已经变了。

**但这是实测结论，不是不变量。** 复发时仍按这三步查，别先改框架：
1. 在组件体第一行加临时计数（**不是** `onMounted` —— 重挂和重建会混在一起）；
2. 在 `onMounted` 里存 `new Error().stack`：栈里若出现自己模块里的函数在 `set value` 之下，就是被自己的写触发的重建；
3. 二分：把可疑跳转推到微任务 / 宏任务，若症状消失即命中本条。
   在**调用处**包一层即可；改 `router.ts` 会把"框架保证同步"这件事悄悄推翻。


## 「编译期"静默编错"的几种写法」

**现象**：编译通过、构建通过，运行期才发现值不对。

**根因**：下面这些写法没有真实用例 ⇒ 编译器**不做检测**，只能靠写法纪律：
* `class={['a','b']}` → `class="a,b"`（对象同理 → `class="[object Object]"`）；
* `style={{ color: 'red' }}` → `style="[object Object]"`（字符串可以）；
* `ref={el}`（模板引用）→ 元素上多一个字符串属性；
* `onclick={fn}`（小写）→ 属性值是函数源码，不是事件（判据是 `on` 开头且第三个字符大写）；
* 块体 `.map()` 回调 → 不建 `createFor`，退化成整块重建。

**现在怎么防**：写代码前把这张表看一遍；要精确的事件类型就自己标注（`(e: InputEvent) => …`）。
会**抛错**的那批（非 map 位置的 `key`、指令式属性、`@click`、组件上的 spread、空元素带子节点、
条件分支不是 JSX / null、组件写在静态位置）由编译期负例守着，不会静默通过。

## 「JSX 空白语义」

**现象**：编译出来的文本与源码"看起来"不一致 —— 行间换行与缩进被保留、单行纯空白折成一个
空格、跨行的纯空白整段消失；`耗时 {x}` 里 `耗时` 后面的空格有时被裁掉。

**根因**：JSX 的空白不是"照抄源码"，也不等于 Babel 那套清理规则。

**现在怎么防**：记住规则 —— **整段纯空白时"单行折成一个空格、跨行丢掉"；否则只裁掉含换行的
首尾空白段。** 所以：
* `\n    第一行\n    第二行\n  ` ⇒ `第一行\n    第二行`（行间换行与缩进原样保留）；
* `a  <b>c</b>  d` ⇒ 原样（单行不折叠）；
* `\n    <b>x</b>\n    <i>y</i>\n  ` ⇒ `<b>x</b><i>y</i>`（跨行纯空白整段丢掉）；
* `\n  耗时 {x}` 里 `耗时 ` 后面那个空格是**行内空格**，必须留着。

## 「列表复用：key、positional、块体 map」

**现象**：列表重排后行内输入框失焦、光标跳到末尾；或者反过来，明明可以搬动的行被整表重建（`onMounted` 重跑、输入内容丢失）。也可能 key 明明写了却没生效。

**根因**：`createFor` 的复用策略由 key 与"渲染体读没读下标"共同决定：key 不变 ⇒ 搬动同一个
节点，同一个 key 但对象换了 ⇒ 重建那一行，没有 key ⇒ 用下标；读了 `.map()` 的第二个参数
（下标）⇒ 重排时**重建那一行**（内容真的依赖位置），没读 ⇒ **搬动**（保住行内焦点与光标）。

**现在怎么防**：
* key 用稳定 id，别用会变的（拿下标当 key，数据一重排等于每行都在重建）；
* 只有"箭头函数 + 函数体直接是一个 JSX 表达式"这一种形状会编成 `createFor`，块体回调、调辅助函数、静态数组都退化成一次性 `setNodes`（key 被忽略）；
* 片段作为 `.map()` 的返回值**不能带 key**（片段没有属性），会按下标复用；
* 新建的行是**正序**插入的 —— `<select>` 的默认选中项由"第一个被插进来的选项"决定；
* 想知道自己那处编成了哪种：看产物里 `createFor` 的最后一个布尔参数。

## 「与 Vapor 的已知差异」

**现象**：同一份页面从 Vue / Vapor 换过来，行为对不上，而且 lite 这边是**故意的**。

| | Vapor | lite |
|---|---|---|
| 属性绑定粒度 | 一个模板里的动态属性共用一条 `renderEffect` ⇒ 改 A 会顺带重写 B（典型后果：`<select>` 旁边输入框一变，下拉框被写成空） | 一个绑定一条 effect，改 A 不动 B |
| 列表重排 | keyed diff 不区分"读没读下标"，一律能搬就搬 | 区分：读了下标就重建那一行，没读才搬 |
| 卸载 | 按组件实例卸载 | 按节点移除（子树里的绑定销毁 + `onUnmounted` 跑） |
| 循环写入 | 调度器 + 警告 | 直接抛错（100 层/轮上限） |
| 动态位置 | 运行期走位（`template(html, n)` + `child` / `next` / `txt`） | 编译期把 `childNodes[i]` 折进源码 |

**现在怎么防**：别拿"与 Vue 逐字符一致"当验收 —— 两侧都坏掉时"一致"也会绿；要写"这一侧必须
等于什么"的绝对断言。上面这些差异本身不是回归。

## 「这些错是怎么被照出来的（验收方法）」

**现象**：好几轮里"测试全绿"与"实际在错"同时存在。

**根因**：夹具数据静止（加载一次就不动）而真实运行时信号随时在变；无头 Chrome 用干净 profile，锚点不会被摘；用例用**纯文本**动态子节点时走的是文本快路径，碰不到 `insert`；应用里的 `try/catch` 会把 effect 的异常吞掉（页面全空而 `window.onerror` 一声不响）；"两侧一致"时两侧同挂它也绿。

**现在怎么防**：
* 判据要**绝对**（"这一侧必须等于 X"），不要"两侧一致"；
* 每条门禁都要问"它红了会不会真的红"：把防御摘掉，用例必须变红；
* 核心路径的改动：先量出可复现的数字 → 定位到具体代码路径 → 改 → **同一个测量脚本量到不变**，才推；
* 抓异常不能只挂 `window.onerror`，用 `--dump-dom` 把栈带出来；
* 单步失败不要把整轮带崩；路由匹配要带前导斜杠；每一步等 DOM 稳定后再判。

框架自己的门：`npm run gates` / `test:compiler` / `test:demo` / `test:bench`，见 [`design.md`](design.md) §7。
